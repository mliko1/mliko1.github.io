用微信云开发从零做一个「匿名心事邮局」小程序（课程实战复盘）

mliko1

September 26, 2026

大家好呀 🐾 这是我的第一个课程项目复盘。上学期我们有一门「开源软件开发」实践课，要求做一个能真正上线的作品。我做了个叫 「匿名心事邮局」 的微信小程序——一个温柔的情绪树洞：你可以把心事写成一封信投进邮局，也能随机收到别人的心事，再回一封温暖的信。

这篇博客把从 0 到上线的全过程摊开来讲，重点放在微信云开发这套零成本方案和几个审核合规的坑，希望对做小程序新手的朋友有用。

一、为什么要做这个小程序

现在大家压力都不小，但未必愿意跟熟人倾诉。市面上虽然有树洞类 App，但大多要注册、要填手机号，反而让人不敢说真话。

我的核心想法很简单：绝对匿名 + 极简。用户进来不需要注册，系统直接发一个随机昵称（比如「害羞的小猫 0821」），写完就能投信。这样既能保护隐私，又降低了倾诉的心理门槛。

选题小建议：课程项目别一上来就做「大而全」的东西。一个能戳中真实痛点的小功能，比十个半成品更打动人，也更容易在答辩时讲清楚。

二、技术选型：为什么选微信云开发

做小程序绕不开「后端放哪」的问题。传统的做法是租一台云服务器 + 买域名 + 备案，对学生来说又贵又麻烦。

我最后选了 微信云开发（CloudBase），原因很实在：

维度传统方案微信云开发
服务器自己租 ECS免服务器
域名/备案必须不需要
用户登录自己写鉴权自带 openid
起步成本几十~几百/月免费额度够用
上线复杂度高低

云开发把 云数据库（文档型）、云函数（Node.js）、云存储、以及内容安全 API 打包好了，小程序端直接用官方 SDK 调用，非常适合个人小项目「零成本部署」。

三、项目结构

整个工程非常轻量，没有后端仓库，逻辑分散在「前端页面 + 云函数」里：

miniprogram/
├── pages/
│   ├── index/        # 首页：投信入口
│   ├── mailbox/      # 树洞信箱：随机读信 + 回信
│   └── mine/         # 我的：查看自己投出的信
├── cloudfunctions/
│   ├── sendLetter/   # 发信（含内容安全审核）
│   ├── getRandomLetter/  # 随机取一封别人心事
│   └── replyLetter/  # 回信
├── utils/
└── app.js / app.json

核心数据存在云数据库的一个集合 letters 里，每条记录大致长这样：

{
  "_openid": "用户唯一标识（云开发自动写入）",
  "nickname": "害羞的小猫 0821",
  "content": "今天答辩好紧张，但是尽力了……",
  "mood": "焦虑",
  "replies": [],
  "createdAt": "2026-09-20T14:03:00Z",
  "status": "published"
}

注意：我们不存任何真实个人信息，昵称是前端随机生成的，数据库只靠 _openid 区分用户。这是「匿名」能成立的关键。

四、核心功能实现

1. 匿名发信

前端收集心情标签和信件内容，调用云函数 sendLetter。云函数里第一件事不是存库，而是先过内容安全审核（见第五节），通过后才写入：

// cloudfunctions/sendLetter/index.js
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const db = cloud.database()

exports.main = async (event) => {
  const { content, mood } = event
  const openid = cloud.getWXContext().FROM_OPENID

  // 1. 内容安全检测（必须，否则过不了审核）
  const sec = await cloud.openapi.security.msgSecCheck({ content })
  if (sec.result.suggest !== 'pass') {
    return { ok: false, msg: '内容不太合适，换种说法试试呀～' }
  }

  // 2. 生成随机匿名昵称
  const nickname = randomNickname()

  // 3. 写入数据库
  await db.collection('letters').add({
    data: {
      _openid: openid,
      nickname,
      content,
      mood: mood || '平静',
      replies: [],
      createdAt: new Date(),
      status: 'published'
    }
  })
  return { ok: true }
}

2. 树洞收信（随机读信）

「邮局」的浪漫在于：你不知道会收到谁的心事。用云数据库的聚合管道做随机抽样最稳：

// cloudfunctions/getRandomLetter/index.js
const res = await db.collection('letters')
  .aggregate()
  .match({ status: 'published' })
  .sample({ size: 1 })   // 随机抽 1 封
  .end()

前端拿到后展示内容 + 心情标签，并提供一个「回信」按钮，回信同样走内容安全审核再写回 replies 数组。

五、平台审核合规：最容易翻车的环节

微信对内容类小程序审核很严，没有内容安全机制基本必被拒。我踩过两个坑，记下来给大家避雷：

  1. 文本必须过 security.msgSecCheck。用户产生的文字（信件、回信）在入库前都要检测，命中敏感词就拒绝。图片类要用 imgSecCheck。
  2. 隐私与匿名要写清楚。虽然我们不收集个人信息，但小程序后台的「用户隐私保护指引」还是要如实填写「我们如何处理用户数据」，并在页面放一句隐私说明，审核员会看。

经验：把内容安全当成「功能的一部分」而不是「上线前的补丁」。越早接入，返工越少。

六、部署上线（零成本）

云开发的部署简单到有点不真实：

  1. 微信开发者工具里「上传」代码，填版本号和备注；
  2. 到 微信公众平台 → 版本管理 → 提交审核；
  3. 审核一般 1~2 天，通过后「全量发布」即可；
  4. 全程没有服务器、没有域名、没有费用，免费额度完全覆盖课程项目的访问量。

唯一要花钱的是「认证费」（300 元/年，个人主体可免，但部分类目需要）。课程项目用个人主体 + 非特殊类目就能跑通。

七、给新手的几点建议

  • 先跑通最小闭环：发信 → 读信 → 回信，三个云函数就够讲一个完整故事。
  • 注释写详细：课程项目答辩时，老师更看重构思和代码可读性，不是花活。
  • 云开发免费额度够用，但注意调用频率，批量操作（如聚合）要控制次数。
  • 审核是项目的一部分，别等到最后一天才提交。

一个小程序从想法到上线，最有成就感的不是代码本身，而是「真的有陌生人在用你写的东西倾诉」。如果你也在做课程项目，欢迎在评论区聊聊你的选题 🐱
