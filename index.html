用微信云开发从零做一个「匿名心事邮局」小程序（课程实战复盘）

大家好呀 🐾 这是我的第一个课程项目复盘。上学期我们有一门「开源软件开发」实践课，要求做一个能真正上线的作品。我做了个叫 「匿名心事邮局」 的微信小程序——一个温柔的情绪树洞：你可以把心事写成一封信投进邮局，也能随机收到别人的心事，再回一封温暖的信。

这篇博客把从 0 到上线的全过程摊开来讲，重点放在微信云开发这套零成本方案和几个审核合规的坑，希望对做小程序新手的朋友有用。

一、为什么要做这个小程序

现在大家压力都不小，但未必愿意跟熟人倾诉。市面上虽然有树洞类 App，但大多要注册、要填手机号，反而让人不敢说真话。

我的核心想法很简单：绝对匿名 + 极简。用户进来不需要注册，系统直接发一个随机昵称（比如「害羞的小猫 0821」），写完就能投信。这样既能保护隐私，又降低了倾诉的心理门槛。

选题小建议：课程项目别一上来就做「大而全」的东西。一个能戳中真实痛点的小功能，比十个半成品更打动人，也更容易在答辩时讲清楚。

二、技术选型：为什么选微信云开发

做小程序绕不开「后端放哪」的问题。传统的做法是租一台云服务器 + 买域名 + 备案，对学生来说又贵又麻烦。

我最后选了 微信云开发（CloudBase），原因很实在：

维度传统方案微信云开发
服务器自己租 ECS免服务器
域名/备案必须不需要
用户登录自己写鉴权自带 openid
起步成本几十~几百/月免费额度够用
上线复杂度高低

云开发把 云数据库（文档型）、云函数（Node.js）、云存储、以及内容安全 API 打包好了，小程序端直接用官方 SDK 调用，非常适合个人小项目「零成本部署」。

三、项目结构

整个工程非常轻量，没有后端仓库，逻辑分散在「前端页面 + 云函数」里：

miniprogram/
├── pages/
│   ├── index/        # 首页：投信入口
│   ├── mailbox/      # 树洞信箱：随机读信 + 回信
│   └── mine/         # 我的：查看自己投出的信
├── cloudfunctions/
│   ├── sendLetter/   # 发信（含内容安全审核）
│   ├── getRandomLetter/  # 随机取一封别人心事
│   └── replyLetter/  # 回信
├── utils/
└── app.js / app.json

GitHub 协作开发学习笔记——以心情气象站项目为例

为什么学 GitHub

GitHub 不只是一个代码托管平台，更是开源协作的核心基础设施。这学期通过「心情气象站」（MoodMeteorology）项目，我从零开始学习了 GitHub 的完整工作流，包括仓库管理、Issue、Pull Request、Code Review、CI/CD 和版本发布。下面是我的学习记录。

1. 仓库与项目结构

我们团队的项目仓库地址：MoodMeteorology

项目采用 Node.js 后端 + 前端静态页面架构，主要文件结构：

├── treehole（1）/          # 树洞模块源码
├── server.js              # 后端入口
├── package.json           # 依赖配置
├── README.md              # 项目文档
├── LICENSE.md             # MIT 许可证
└── CONTRIBUTING.md        # 贡献说明

一个好的开源项目需要包含：

  • README：项目介绍和使用说明

  • LICENSE：开源许可证（我们选了 MIT）

  • CONTRIBUTING：贡献者指南

2. Issue 驱动开发

我们通过 Issue 来管理所有开发任务，这是学到的最重要的协作方式之一。
