GitHub 协作开发学习笔记——以心情气象站项目为例

为什么学 GitHub

GitHub 不只是一个代码托管平台，更是开源协作的核心基础设施。这学期通过「心情气象站」（MoodMeteorology）项目，我从零开始学习了 GitHub 的完整工作流，包括仓库管理、Issue、Pull Request、Code Review、CI/CD 和版本发布。下面是我的学习记录。

1. 仓库与项目结构

我们团队的项目仓库地址：MoodMeteorology

项目采用 Node.js 后端 + 前端静态页面架构，主要文件结构：

├── treehole（1）/          # 树洞模块源码
├── server.js              # 后端入口
├── package.json           # 依赖配置
├── README.md              # 项目文档
├── LICENSE.md             # MIT 许可证
└── CONTRIBUTING.md        # 贡献说明

一个好的开源项目需要包含：

  • README：项目介绍和使用说明

  • LICENSE：开源许可证（我们选了 MIT）

  • CONTRIBUTING：贡献者指南
